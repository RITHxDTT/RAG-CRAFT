# RAG Craft V2 — Full Frontend Demo Implementation

## 1. Project Goal

Update and complete the existing **RAG Craft V2** application.

RAG Craft is a multi-tenant platform where users can create AI chatbots, configure their behavior, manage knowledge sources, test chatbots, and publish them through multiple channels.

For the CURRENT VERSION, the main goal is to create a **fully interactive frontend demo** that can be deployed to Vercel and shared with the team.

The team must be able to:

- Sign in
- Sign up
- Use Admin/User roles
- Edit profile
- Create and manage chatbots
- Configure chatbot settings
- Manage mock knowledge sources
- View document processing workflow
- Test chatbot UI
- Configure channel access
- Generate public share links
- Configure web widgets
- Configure Telegram integration
- View analytics
- Navigate the complete Admin/User workflow

IMPORTANT:

Do NOT implement the real AI/RAG infrastructure yet.

Do NOT require:

- PostgreSQL
- FastAPI
- Qdrant
- Ollama
- Real embeddings
- Real document chunking
- Real vector indexing
- Real Telegram Bot API
- Real AI generation

Use browser storage and mock services for the current demo.

# 3. Architecture Requirement

VERY IMPORTANT:

Do NOT directly call `localStorage` everywhere inside pages/components.

Create a clean service/repository architecture.

Example:

UI Components
↓
Service Layer
↓
Repository / Storage Layer
↓
localStorage / IndexedDB

Suggested structure:

```text
src/
├── app/
├── components/
├── features/
├── services/
│   ├── auth.service.ts
│   ├── user.service.ts
│   ├── chatbot.service.ts
│   ├── knowledge.service.ts
│   ├── channel.service.ts
│   ├── conversation.service.ts
│   └── analytics.service.ts
├── repositories/
│   ├── auth.repository.ts
│   ├── chatbot.repository.ts
│   ├── knowledge.repository.ts
│   └── channel.repository.ts
├── storage/
│   ├── local-storage.ts
│   └── indexed-db.ts
├── types/
├── mocks/
└── utils/
```

The purpose is to make future migration easy.

CURRENT:

```text
UI
 ↓
Service
 ↓
localStorage
```

FUTURE:

```text
UI
 ↓
Service
 ↓
FastAPI
 ↓
PostgreSQL / Qdrant
```

Do not tightly couple the UI to localStorage.

# 49. Future Backend Migration

Code MUST be structured so that browser storage can later be replaced.

Future architecture:

```text
Next.js
   ↓
API Gateway / Ingress
   ↓
FastAPI Services
   ├── Authentication
   ├── User
   ├── Chatbot
   ├── Knowledge
   ├── Channel
   ├── Conversation
   ├── Analytics
   └── RAG
        ↓
 ┌─────────────┬──────────┬──────────────┐
 PostgreSQL    Qdrant     Ollama/LLM
```

Therefore:

- Use TypeScript interfaces
- Use service abstraction
- Use repository abstraction
- Keep storage logic separate
- Keep business logic separate from UI
- Avoid direct storage access in components
- Keep IDs backend-friendly
- Include `createdAt` and `updatedAt`
- Include `ownerId`
- Keep relationships explicit
